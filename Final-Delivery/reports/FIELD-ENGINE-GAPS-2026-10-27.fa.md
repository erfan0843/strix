## ۲) ستاره‌ها (R1) — اصلاح و اثبات

یک الگوریتم صریح جایگزین منطق «مقدار مطلق در برابر اندیس» شد (`form.html`، `setRatingState(box,value)`):

- مقدار معتبر = عدد صحیح داخل `[min,max]`؛ مقدار بازیابی‌شدهٔ خارج از بازه → **خالی** (نه ستارهٔ اشتباه).
- روشن = ستاره‌های `min ≤ v ≤ value`؛ `aria-checked="true"` فقط روی ستارهٔ `v === value`؛ `tabindex` روبان: ستارهٔ انتخاب‌شده یا (اگر خالی) اولین ستاره.
- برچسب `[data-qrate-label]` «N ستاره» و ورودی پنهان، همان مقدار؛ `__NORA_PUBLIC_FORM_COLLECT()` همان مقدار را می‌فرستد.
- سرور (`responses.py`): rating/scale/bars فقط عدد صحیح داخل بازه (قبلاً اعشار قبول می‌شد).
- راهنمای پیش‌فرض ستاره در فرم‌ساز از بازهٔ واقعی ساخته می‌شود («۲ کم، ۴ زیاد.»، «یک ستاره؛ زدن آن یعنی انتخاب.») و راهنمای سفارشی مالک دست نمی‌خورد.

اثبات: `e2e-rating.cjs` پس از اصلاح **۴۵/۰** (قبل: ۳۷/۸)؛ سناریوها: پیش‌فرض ۱–۵، سفارشی ۲–۴، تک‌مقداری ۳–۳ (سرور اجازه می‌دهد)، انتخاب هر ستاره، پاک‌کردن، ذخیرهٔ پیش‌نویس و بارگذاری مجدد، تغییر بازه پس از پیش‌نویس (مقدار ۵ با بازهٔ تازهٔ ۲–۴ → خالی)، هم‌خوانی مقدار/`aria-checked`/شمار روشن/پاسخ ارسالی، ۴۲۲ سرور برای ۵ و ۲٫۵. تصویرها: `evidence/.../shots/rating-*` (پیش و پس).

## ۴) قرارداد `FIELD_SETTINGS` — منبع واحد واقعی

هر عضو ثبت اکنون این اعضا را دارد و چهار تابع ویرایشگر **فقط روی ثبت حلقه می‌زنند**:

| عضو | نقش |
|---|---|
| `id`, `keys` | شناسهٔ پایدار و کلیدهای دادهٔ روی فیلد (یکتا؛ آزمون ⑬) |
| `box`, `display`, `when`/`common` | ظرف DOM و شرط نمایش (نوع + خود فیلد، مثلاً `verify` قدیمی) |
| `cap` | شناسهٔ همین تنظیم در `field_settings` قرارداد سرور (آزمون ⑬ وجودش را در `form_capabilities.py` چک می‌کند) |
| `render(f)` | پرکردن کنترل‌ها از فیلد (`renderFieldEditor`) |
| `validate(f)` → `{message,target}` | نخستین اشکال کنار همان کنترل؛ پنجره باز می‌ماند و فیلد دست نمی‌خورد (`saveField`) |
| `apply(f)` / `clear(f)` | نوشتن کنترل‌ها در پیش‌نویس؛ پاک‌کردن وقتی برای نوع فعلی نمایش داده نمی‌شود |
| `dirty(f)` | تغییر ذخیره‌نشده (`editorControlsChanged`، نگهبان بستن) |
| `convert(next,from,to)` / `consequence(f,to)` | تغییر نوع: تبدیل داده + جملهٔ پیامد (`applyTypeChange`/`typeChangeConsequences`) |

**مرزهای مستند که ثبت پوشش نمی‌دهد (ساختار تکراری نامیده نمی‌شود، ولی صادقانه فهرست شده):**
1. ویرایشگر گزینه‌ها و ویرایشگر شرط‌ها مستقیماً روی `FIELD_DRAFT`/`conditionDraft` می‌نویسند؛ dirty آن‌ها از عکس پیش‌نویس (`fieldDraftSnapshot`) می‌آید، نه از `dirty()`.
2. `applyTypeChange` هنوز برای opts/bounds/placeholder/upload/verify منطق خانوادهٔ نوع (`TYPE_FAMILIES`) را خودش دارد؛ ثبت فقط برای تنظیم‌های تازه (`length`, `integer`) `convert/consequence` دارد. انتقال بقیه به ثبت = کار بعدی، بدون تغییر رفتار.
3. `#fdValidationBox` (بخش‌بندی بصری) از فهرست ثابت `VALIDATION_SECTION_SETTINGS` مشتق می‌شود.
4. `renderProfileControl`/`renderTypeChangeBox` نمایش ظرف خودشان را هم تنظیم می‌کنند (سازگار با ثبت؛ آزمون ⑬ برابری را چک می‌کند).

آزمون هم‌خوانی (`builder-fields.test.mjs` ⑬): شناسه‌ها/کلیدها یکتا؛ هر `#shField [id$="Box"]` ↔ یک تنظیم ثبت‌شده (بی‌صاحب/گم‌شده = خطا)؛ برای **همهٔ نوع‌های قابل‌افزودن**: ظرف‌های نمایان = ثبت، و کلیدهای ذخیره‌شده ⊆ ثبت ∪ پایه؛ هر `cap` در قرارداد سرور تعریف شده. همین بررسی در مرورگر واقعی برای ۳۰ نوع (`e2e-field-types`، «visible setting boxes == FIELD_SETTINGS registry»).

قرارداد سرور تازه: `GET /api/public/forms/capabilities` → `field_settings` (۱۵ ورودی) با `status` (`server` / `client_display` / `conditional` / `unavailable`)، `types`، `keys`، سقف‌ها (`max_by_type`, `ranges`, `max_options`…) و `reason`. فرم‌ساز برای `length`/`integer` نوع‌ها و سقف را از همین قرارداد می‌خواند (با پیش‌فرض محلی وقتی قرارداد در دسترس نیست).

## ۵) تنظیم‌های نوع‌محور — جدول نوع × تنظیم × رفتار واقعی

ستون «زنجیره» = کنترل → ذخیره → بازگشایی → readiness → اعتبارسنجی سرور → فرم عمومی.

| خانواده / نوع | تنظیم | وضعیت | زنجیره / اثبات |
|---|---|---|---|
| متن (`text`, `area`, `address`, `location`, `fullname`) | عنوان، راهنما، اجباری | سروری | e2e-field-types ۳۰ نوع |
| | متن داخل کادر (`placeholder`) | `client_display` (فقط نمایش؛ سرور بررسی نمی‌کند — در قرارداد همین نوشته شده) | e2e-field-types |
| | **حداقل/حداکثر نویسه (`minLen`/`maxLen`)** — **تازه** | سروری؛ سقف نوع: text/address ۱۰۰۰، area ۳۰۰۰، location ۱۸۰، fullname ۱۲۰ | builder-fields ⑭، pytest `test_text_length_and_integer_settings_are_enforced_and_published`, `test_invalid_length_settings_block_publish_with_field_reference`، **`e2e-length-integer` ۴۴/۰**: ویرایشگر (min>max، بیش از سقف، تمرکز روی کنترل)، سرور (`minLen:3,maxLen:8`)، بازگشایی، readiness `invalid_length_range` + دکمهٔ «بازکردن پرسش» → تمرکز `#fdMinLen`، فرم عمومی (`maxlength=8`، یادداشت «دست‌کم ۳ نویسه · حداکثر ۸ نویسه»، پیام «باید دست‌کم ۳ نویسه باشد»)، API (پیش‌نویس ناقص حداقل را رد نمی‌کند؛ حداکثر همیشه؛ ثبت نهایی حداقل را رد می‌کند) |
| | اعتبارسنجی نوع | mobile `09…` ۱۱ رقم؛ nid ۱۰ رقم؛ email RFC ساده؛ در مرورگر و سرور یکسان | e2e-field-types |
| عدد / مبلغ (`number`, `amount`) | حداقل/حداکثر (`min`/`max`) | سروری؛ مبلغ منفی هرگز | e2e-field-types، e2e-field-engine |
| | **فقط عدد صحیح (`integer`)** — **تازه** | سروری؛ `inputmode=numeric`، placeholder «مثلاً ۱۲»، یادداشت «فقط عدد صحیح»، پیام «باید عدد صحیح (بدون اعشار) باشد»؛ راهنمای پیش‌فرض عدد با روشن‌شدن به نسخهٔ بدون «ممیز» عوض می‌شود | e2e-length-integer، builder-fields ⑭ |
| | گام تغییر (`step`)، تعداد رقم اعشار، اعداد منفی برای `number` | **فاقد پیاده‌سازی** (در قرارداد: `integer.reason` صریح می‌گوید)؛ منفی برای number مجاز، برای amount ممنوع | گزارش‌شده |
| گزینه‌ای (`choice`, `dropdown`, `multi`, `imgchoice`, `yesno`, `gender`, `marital`) | مدیریت گزینه‌ها، یکتا و غیرخالی، ترتیب | سروری (سقف ۱۰۰ گزینه، برچسب ۱۲۰) | e2e-field-types (تکراری رد می‌شود)، e2e-field-engine (جابه‌جایی) |
| | حداقل/حداکثر انتخاب (`multi`) | سروری | e2e-field-types |
| | گزینهٔ پیش‌فرضِ از‌پیش‌انتخاب‌شده | **فاقد پیاده‌سازی** (در قرارداد `options.reason`) | گزارش‌شده |
| | نمایش بر اساس مدل | امتیاز گزینه فقط در نظرسنجی و فقط محلی | builder-fields ⑮ |
| تاریخ/زمان (`date`, `time`, `datetime`, `slot`) | قواعد تاریخ معتبر (`YYYY/M/D`, `H:MM`) | سروری | e2e-field-types |
| | حداقل/حداکثر تاریخ و ساعت | **فاقد پیاده‌سازی** — در قرارداد `temporal_bounds = unavailable`؛ هیچ کنترلی نمایش داده نمی‌شود (نه کنترل تزئینی) | گزارش‌شده |
| بومی (`province`, `uni`, `edu`, `job`, `marital`) | گزینه‌های ثابت/پیشنهادی، «سایر» با پاسخ سفارشی | سروری (پاسخ آزاد با سقف طول نوع) | e2e-field-types (`uni` «سایر» → «دانشگاه آزمون») |
| ستاره / مقیاس / نوار | بازه، فقط صحیح، نمایش مقدار انتخابی | سروری | e2e-rating ۴۵/۰، e2e-field-types |
| پذیرش قوانین | متن، اجباری | سروری | بخش ۳ |

**هیچ تنظیم تازه‌ای تزئینی نیست**: آزمون ⑬ تأیید می‌کند هر ثبت دست‌کم `render` یا `apply` دارد و هر ظرف DOM صاحب دارد.

## ۶) رفتار مدل‌محور — ماتریس ۹ مدل

| مدل | وضعیت قرارداد | تنظیم‌های ویژه در فرم‌ساز | قواعد پاسخ / گزارش | انتشار |

| ثبت اطلاعات | limited | هیچ ویژه | پاسخ، CSV | قابل انتشار |
| سفارش | **unavailable** | کاشی غیرفعال | — | **غیرقابل انتشار** (readiness `model_not_publishable`) |
| رأی‌گیری | limited | هیچ ویژه | رأی با فرم؛ یکتایی/محرمانگی تضمین نمی‌شود | قابل انتشار |

اثبات: `builder-fields.test.mjs` ⑮ (آزموده‌شده): همراهان/بلیت فقط در ثبت‌نام نمایان؛ `guestsOn` در payload بقیهٔ مدل‌ها `false` ولی در حالت فرم‌ساز می‌ماند (بازگشت به ثبت‌نام → برمی‌گردد؛ دادهٔ معتبر بی‌صدا دور ریخته نمی‌شود)؛ جعبهٔ امتیاز و `scoring.enabled` فقط برای نظرسنجی؛ آزمون/مسابقه `scoring=false`؛ کاشی سفارش غیرفعال؛ توضیح کاشی‌ها قابلیت‌های ثابت‌نشده را صادقانه می‌گویند. smoke ۶الف و بخش مدل‌ها نیز.

**تصمیم موردنیاز (ثبت‌شده، پیاده‌سازی نشده):** قواعد آزمون (کلید پاسخ، نمرهٔ سروری، زمان)، مسابقه (رتبه/قرعه)، حضور و غیاب (تأیید حضور واقعی/QR)، رأی‌گیری (یک رأی برای هر شخص، محرمانگی)، سفارش (گردش سفارش و پرداخت امن). هیچ‌کدام بدون قرارداد محصول ساخته نشد و هیچ‌کدام «فعال» نمایش داده نمی‌شود.

## ۷) مسیر UX انتخاب‌گر — بررسی E2E

`e2e-picker-ux.cjs` در مرورگر واقعی (۱۴۴۰ و ۳۹۰) — **۲۳/۰**:

| مسیر | رفتار (آزموده‌شده) |
|---|---|
| باز کردن از ابتدا / انتها / بین | **تازه**: «+» بالا = ابتدای فهرست، «+» پایین = انتها، منوی هر پرسش «افزودن پرسش پس از این»؛ یادداشت جایگاه در انتخاب‌گر («در ابتدای فهرست افزوده می‌شود» / «پس از پرسش ۲»)؛ اعلام زنده در `#fieldReorderStatus`؛ بستن بدون افزودن، جایگاه را نگه نمی‌دارد |
| یافتن با دسته + عبارت فارسی | «تاریخ» دو الگوی هم‌نوع (`birth-date`/`jalali-date`) را می‌آورد؛ «عکس» ردیف غیرفعال با دلیل سرور |
