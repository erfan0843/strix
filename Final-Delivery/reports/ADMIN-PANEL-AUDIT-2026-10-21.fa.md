### ۱.۳ نقش‌ها (منبع: `backend/roles.py`)

## ۲. ماتریس دسترسی — ادعای کد + نتیجهٔ آزمون واقعی API (`scripts/adm-matrix.mjs`)
ستون‌ها کد وضعیت واقعی هستند؛ مالک با نشست واقعی، مدیر با `staff-login` واقعی، «عضو» حساب تلفنی بدون نقش، «ناشناس» بدون کوکی.

| endpoint | مالک | مدیر | عضو بی‌نقش | ناشناس |
|---|---|---|---|---|
| `GET /api/admin/inbox` | 200 | 200 | 403 | 401 |
| `GET /api/admin/reports/summary` | 200 | 200 | 403 | 401 |
| `GET /api/forms`, `GET /api/forms/{id}`, `GET …/responses` | 200 | 200 | 403 | 401 |
| `POST /api/forms/{id}/publish`, `/pause` | 409 (نسخهٔ عمداً غلط) | 401 | 401 | 401 |
| `GET /api/owner/accounts`, `PUT …/role`, `PUT …/manager-credentials` | 200 | 401 | 401 | 401 |
| `GET /api/owner/service-settings`, `GET /api/owner/data/status` | 200 | 403 | 403 | 401 |
| `GET /api/owner/site-content`, `PATCH` | 200/400 | 401 | 401 | 401 |
| `GET /api/cooperation-requests` | 200 | 401 | 401 | 401 |
| `GET /api/integrations/status`, `GET /api/health` | 200 | 200 | 200 | 200 (عمومی؛ بدون secret) |
| `POST /api/outbox` | 400 | 400 | 400 | 400 (اسکلت؛ هیچ ارسالی انجام نمی‌دهد) |

سناریوهای امنیتی (نتیجهٔ واقعی):
- **ارتقای مجوز با API مستقیم:** مدیر نتوانست به حساب دیگری نقش بدهد یا اعتبارنامهٔ مدیر بسازد (401).
- **لغو فوری:** پس از `PUT role=null` توسط مالک، همان نشست مدیر بلافاصله روی `/api/admin/inbox` و `/api/account/me` 401 گرفت (نشست‌های `manager-password` باطل می‌شوند).
- **خروج مالک:** بعد از `POST /api/auth/logout`، `/api/owner/accounts` → 401.
- در پنل: مدیر فقط داشبورد/رویدادها/کاربران/فرم‌ها را می‌بیند؛ «حساب‌ها و نقش‌ها» و تب‌های تنظیمات برای او رندر نمی‌شود و اگر دستی `#settings` باز کند، داشبورد نمایش داده می‌شود.

ماتریس مجوزها (از `roles.py`): مالک = همه (۴۰ مجوز). مدیر = `ev_*`, `attendance`, `certificate`, `fm_create/fm_responses/fm_export`, `receipt_approve`, `us_view/us_edit/us_approve/us_block/us_notes/us_export`, `sp_*`, `qa_*`, `bc_*`, `pr_*`, `dev_*`, `rp_view/rp_export`. سرپرست باشگاه = مدیر + `cl_member/cl_session/cl_cert/cl_content`. فقط مالک: `finance`, `role_assign`, `sys_fields`, `sys_settings`, `sys_backup`, `cert_final`, `user_delete`, `public_roster`, `cl_dues`, `sys_points`.

## ۴. اصلاح‌های انجام‌شده (فایل‌ها و مسیرها)

کامیت‌ها روی همین شاخه، به ترتیب: `e00efeb` (backend)، `96f6894` (backend، فیلتر خانوادهٔ عملیات)، `7a9c499` (frontend + آزمون‌ها)، و کامیت گزارش/شواهد.

### ۴.۱ ردپای عملیات مدیریتی (A1)
- `backend/models.py`: مدل `AdminAuditEventRecord`؛ `backend/migrations/versions/0026_admin_audit_events.py` (جدول + ایندکس؛ قابل اجرای مجدد با `alembic upgrade head`).

- پنل: تب «امنیت و دسترسی‌ها» → بخش «تاریخچهٔ عملیات» با فیلتر خانوادگی، «موارد قدیمی‌تر»، حالت‌های بارگذاری/خطا/خالی (`admin.js: serverAuditView/loadServerAuditEvents`).
