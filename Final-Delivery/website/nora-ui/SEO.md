# ممیزی ۱۶‌گانهٔ SEO و دادهٔ ساختاریافتهٔ نورا

این راهنما نتیجهٔ بررسی جداگانهٔ هر معیار را ثبت می‌کند. canonical و دادهٔ کسب‌وکار از Host درخواست، fixtureها یا مقدارهای نمونه ساخته نمی‌شوند؛ اتصال عملیاتی دامنه و LocalBusiness تا دریافت اطلاعات واقعی عمداً باز می‌ماند.

## ۱) اتصال دامنهٔ اختصاصی

برنامه فقط از origin صریح و رسمی استفاده می‌کند. برای FastAPI و static Node server، در پیکربندی امن سرویس production مقدار زیر را با origin واقعیِ متعلق به گروه تنظیم کنید:

```text
NORA_PUBLIC_BASE_URL=https://<official-domain>
```

مقدار باید origin عمومی HTTPS باشد، نه نشانی نمونه، IP داخلی، مسیر، query یا دامنه‌ای که متعلق به گروه نیست. Host و Forwarded-Host درخواست هیچ‌گاه مبنای canonical یا sitemap نمی‌شوند. با origin معتبر، canonical صفحه‌های عمومی و پیوندهای sitemap مطلق می‌شوند و `robots.txt` نشانی sitemap را می‌افزاید. بدون آن، canonical در قالب مسیر نسبی باقی می‌ماند، `robots.txt` دامنه‌ای حدس نمی‌زند و `/sitemap.xml` با پاسخ `503` بسته می‌ماند.

**اتصال واقعی DNS هنوز انجام‌شدنی نیست:** نام دامنه، ارائه‌دهندهٔ میزبانی/DNS و مقصد استقرار در اختیار این مخزن نیست. پس از انتخاب و تأیید مالکیت دامنه، دامنه را در میزبان ثبت کنید، فقط رکوردهایی را که همان میزبان اعلام می‌کند (A/AAAA/CNAME) در DNS قرار دهید، TLS را فعال کنید، نسخه‌های alias را به میزبان canonical هدایت کنید و همین origin را در secret/config همهٔ نمونه‌های سرویس بگذارید. IP یا رکورد DNS حدس نزنید؛ سپس `/`, `/robots.txt`, `/sitemap.xml` و canonical را از دامنهٔ واقعی بررسی کنید. Node روی `HOST=0.0.0.0` گوش می‌دهد؛ DNS، TLS و redirect پروتکل/میزبان باید در ارائه‌دهندهٔ استقرار تنظیم شوند.

## ۲) صفحهٔ 404 سفارشی

`/404.html` و مسیرهای HTML ناشناخته صفحهٔ سفارشی فارسی، status واقعی `404`، `noindex` و پیوند بازگشت به خانه/رویدادها دارند. مسیرهای ناشناختهٔ فایل نیز همین صفحه را با status 404 می‌گیرند؛ این صفحه canonical نمی‌گیرد.

## ۳) عنوان منحصربه‌فرد هر صفحه

عنوان خانه، رویدادها، راهنما، ورود، حساب، فرم‌ها و ابزارهای مدیریتی در قالب HTML مستقل است. عنوان صفحهٔ رویداد/مطلب/پروفایلِ منتشرشده سمت سرور از نام همان رکورد ساخته می‌شود؛ پیش‌نویس یا شناسهٔ ناموجود title عمومیِ قابل نمایه‌سازی نمی‌گیرد. بررسی ایستا، title خالی یا تکراری میان فایل‌های HTML پیدا نکرد.

## ۴) توضیحات متای صفحات

فایل‌های HTML توضیح متای اختصاصی دارند. برای صفحه‌های عمومی پویا، description از شرح/خلاصه/زندگی‌نامهٔ همان رکورد منتشرشده ساخته و escape می‌شود. قالب‌های فرم، حساب، ورود، پنل و preview نیز توضیح دارند ولی `noindex` می‌مانند.

## ۵) تگ canonical

خانه و aliasهای آن به `/`، فهرست رویدادها به `/events.html` و صفحه‌های عمومی پویا به مسیر پایدار همان شناسه canonical می‌شوند؛ queryهای رهگیری حذف می‌شوند. با `NORA_PUBLIC_BASE_URL` معتبر، FastAPI و Node نشانی مطلق می‌دهند؛ بدون دامنهٔ تأییدشده، مسیر نسبی امن می‌ماند. صفحهٔ ناموجود، preview و محتوای غیرعمومی canonical ندارند.

## ۶) هدینگ‌های مناسب و منحصربه‌فرد

صفحه‌های عمومی قابل نمایه‌سازی یک H1 روشن دارند. عنوان H1 رویداد/مطلب/پروفایل از همان رکورد عمومی ساخته می‌شود. پوستهٔ ثابت این سه صفحه H1 محتوایی ندارد و `noindex` است تا وقتی backend یک رکورد منتشرشده را تأیید کند؛ صفحهٔ 404 و ابزارهای خصوصی نیز هدینگ مختص خودشان دارند.

## ۷) لینک‌سازی داخلی

خانه و صفحهٔ رویدادها پیوندهای داخلی crawlable به بخش‌های عمومی دارند. جزئیات رویداد، مطلب و پروفایل به صفحهٔ مادر/فهرست مربوط پیوند دارند. مقصدها فقط از projection محتوای عمومی ساخته می‌شوند؛ پیوندی به صفحهٔ private یا پیش‌نویس منتشر نمی‌شود.

## ۸) Breadcrumbs

رویدادها، مطالب و پروفایل‌های server-rendered breadcrumb قابل‌دسترسی در HTML و `BreadcrumbList` در JSON-LD دارند. فهرست رویدادها مسیر خانه → رویدادها را نشان می‌دهد. لینکِ هر breadcrumb به مسیر داخلی پایدار اشاره می‌کند.

## ۹) robots.txt

`/robots.txt` به‌طور پیش‌فرض crawl را فقط برای `/api/` می‌بندد تا خزنده بتواند `noindex` صفحه‌های کاربردی را بخواند؛ خط `Sitemap:` فقط با origin رسمی افزوده می‌شود. `robots.txt` کنترل دسترسی نیست و مجوزهای API همچنان فقط در backend اجرا می‌شوند.

## ۱۰) داده‌های ساختاریافته

خانه و رویدادها JSON-LD با `Organization`, `WebSite` و `WebPage` دارند. محتوای رویداد، مطلب و پروفایلِ منتشرشده به‌ترتیب schema متناسب (`WebPage`, `Article`, `ProfilePage`) و breadcrumb می‌گیرد. مقدارها escape می‌شوند و فقط از محتوای عمومی تأییدشده می‌آیند.

## ۱۱) LocalBusiness schema

`LocalBusiness` پیش‌فرض ندارد و تا وقتی اطلاعات رسمی کامل و تأییدشده روی سرور تنظیم نشود، حذف می‌ماند. تنظیمات لازم:

- `NORA_SEO_BUSINESS_NAME`
- `NORA_SEO_BUSINESS_STREET_ADDRESS`
- `NORA_SEO_BUSINESS_LOCALITY`
- `NORA_SEO_BUSINESS_POSTAL_CODE`
- `NORA_SEO_BUSINESS_COUNTRY_CODE` (کد دوحرفی ISO)
- `NORA_SEO_BUSINESS_TELEPHONE`
- اختیاری: `NORA_SEO_BUSINESS_DESCRIPTION`

اگر هر فیلدی وارد شود، فیلدهای اصلی باید کامل و معتبر باشند؛ FastAPI پیکربندی ناقص را رد می‌کند و static Node server در schema آن را fail-closed حذف می‌کند. نام، نشانی، شهر، کدپستی یا تلفن ساختگی تنظیم نکنید و فقط مکانی را معرفی کنید که واقعاً به کسب‌وکار مربوط است.

## ۱۲) sitemap.xml

با origin رسمی، `/sitemap.xml` در FastAPI خانه، رویدادها و شناسه‌های رویداد/مطلب/پروفایل عمومی را از projection سروریِ allowlist‌شده می‌سازد؛ private، hidden، draft و pending نباید در آن بیایند. Static Node server که DB ندارد فقط خانه و رویدادها را فهرست می‌کند. بدون origin رسمی هیچ sitemap مطلقی منتشر نمی‌شود.

## ۱۳) favicon

`favicon.svg`, `favicon.ico`, آیکون‌های PNG و manifest موجودند، در صفحه‌های HTML معرفی می‌شوند و server فایل‌هایشان را با content type درست سرو می‌کند.

## ۱۴) llms.txt

`/llms.txt` محدودهٔ محتوای عمومی، صفحه‌های قابل استفاده و مرز داده‌های خصوصی را توضیح می‌دهد و دامنهٔ فرضی تثبیت نمی‌کند.

## ۱۵) کاهش حجم bundleهای JavaScript

- `data.js` فقط در حالت صریح `__NORA_TEST_FIXTURE_MODE__ === true` بارگیری می‌شود؛ fixtureهای آزمون حفظ شده‌اند ولی درخواست عادی صفحات عمومی آن را نمی‌گیرد.
- snapshot دانشگاه فقط هنگام نیاز واقعی picker بارگیری می‌شود و Service Worker آن را پیش‌بارگیری نمی‌کند.
- مرکز فرم‌ها (`builder.html`) نیز fixture را فقط در حالت آزمون می‌گیرد و دیگر فونت بزرگِ مختص خروجی گواهی (`cert-font.js`) را در بارگذاری عادی درخواست نمی‌کند؛ فایل برای ابزارهایی که واقعاً به آن نیاز دارند حذف نشده است.
- در محاسبهٔ فایل‌های JavaScript خارجیِ builder، بارگیری عادی از **۵۷۱٬۹۵۵ بایت خام / ۱۹۴٬۶۹۱ بایت gzip** به **۲۲۱٬۹۲۹ / ۶۸٬۰۳۴** رسیده است؛ یعنی `data.js` و `cert-font.js` که در مسیر عادی لازم نبودند، مجموعاً **۳۵۰٬۰۲۶ بایت خام / ۱۲۶٬۶۵۷ بایت gzip** حذف شده‌اند. `admin.js` حجیم‌تر است اما فقط صفحهٔ مدیریت آن را درخواست می‌کند؛ در مسیرهای عمومی SEO بارگیری نمی‌شود.
- Node static server فشرده‌سازی Brotli/Gzip، ETag و cache revalidation دارد؛ FastAPI نیز GZip فعال دارد. `asset-audit.test.mjs` سقف اندازهٔ خام/فشردهٔ `ui.js` و snapshotها را نگه می‌دارد.

## ۱۶) alt تصاویر

تمام تگ‌های `<img>` موجود در قالب HTML/JavaScript باید `alt` معنادار یا `alt=""` برای تصویر تزئینی داشته باشند. `asset-audit.test.mjs` این قالب‌ها را بررسی می‌کند.

## آزمون و محدودیت استقرار

`backend/tests/test_seo.py`, `backend/tests/test_seo_routes.py`, `server.test.mjs` و `asset-audit.test.mjs` origin نامعتبر و Host جعلی، title/description/canonical/H1، محتوای private، breadcrumb/schema، LocalBusiness fail-closed، robots/sitemap، 404، favicon/llms، alt تصاویر و بودجهٔ bundle را بررسی می‌کنند. این بررسی‌ها رفتار کد را تأیید می‌کنند؛ اتصال DNS/TLS واقعی تا وقتی دامنه و میزبان ارائه نشوند قابل تأیید نیست. هیچ preview serverی برای ممیزی اجرا نکنید.
