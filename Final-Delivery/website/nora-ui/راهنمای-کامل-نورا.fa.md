# راهنمای کامل نورا: از صفر تا صد

این فایل برای کسی نوشته شده که پروژه را از ابتدا باز می‌کند، روی کامپیوتر خودش اجرا می‌کند، آزمون می‌گیرد و بعد به سرور می‌برد. هر بخش کوتاه و عملی است.

---

## ۱. نورا چیست؟

نورا سامانهٔ گروه فرهنگی «خط زندگی» است. با آن:

- **عمومی‌ها** رویدادها، کارگاه‌ها، مطالب، پروفایل افراد و نهادها را می‌بینند،
- **کاربران** با شمارهٔ همراه و کد یک‌بارمصرف وارد می‌شوند، حساب و رویدادهای خود را می‌بینند،
- **فرم‌های ثبت‌نام** را با سازندهٔ فرم می‌سازند و پاسخ‌ها را جمع می‌کنند،
- **مدیر (مالک)** از پنل مدیریت رویدادها، کاربران، بنرها و فرم‌ها را کنترل می‌کند،
- **ربات بله** (در بسته‌ی اصلی) اطلاع‌رسانی و ورود را کمک می‌کند.

---

## ۲. این پوشه چیست؟

| فایل | چیست |
|---|---|
| `nora-ui.zip` | **نسخهٔ اصلی و کاربردی**: صفحات، سرور (FastAPI)، پایگاه‌داده، آزمون‌ها و مستندات. |
| `nora-ui-docs-base.zip` | **نمای طراحی**: فقط ظاهر صفحات با داده‌ی نمونه، بدون سرور. برای دیدن طراحی است، نه برای تولید. |

وقتی از `nora-ui.zip` صحبت می‌کنیم، منظور کد اصلی است.

### ساختار `nora-ui`

| مسیر | محتوا |
|---|---|
| `*.html` | صفحات: خانه، رویدادها، رویداد، حساب، ورود، پنل مدیر، فرم‌ساز، فرم عمومی، پست، پروفایل، پشتیبانی، ۴۰۴ |
| `*.js` / `*.css` | منطق و استایل صفحات (`ui.js`، `login.js`، `nora.css`، `glass.css` و …) |
| `backend/` | سرور FastAPI: `app.py` (مسیرها)، `models.py` (جدول‌ها)، `migrations/` (تغییرات پایگاه‌داده)، `tests/` (آزمون‌های سرور) |
| `tools/local-dev.py` | راه‌اندازی امن برای توسعهٔ محلی |
| `*.test.mjs` | آزمون‌های صفحات (Node + jsdom) |
| `.env.local.example` | نمونهٔ تنظیمات؛ **بدون مقدار واقعی** |
| `*.md` | گزارش‌های آزمون، معماری، SEO، فرم‌ساز و وضعیت هر بخش |

---

## ۳. پیش‌نیازها

- **Python 3.11** یا جدیدتر
- **Git** (اختیاری، برای برگرداندن تغییرات)
- **Node.js 20+** (فقط اگر آزمون‌های `*.test.mjs` را اجرا می‌کنید)
- برای نسخهٔ واقعی (سرور عمومی): PostgreSQL و یک دامنه با HTTPS

---

## ۴. اجرای محلی، قدم به قدم

همهٔ دستورها را داخل پوشهٔ `nora-ui` اجرا کنید.

### قدم ۱: محیط Python

```bash
python3 -m venv .venv
source .venv/bin/activate          # ویندوز: .venv\Scripts\activate
pip install -r backend/requirements.txt
```

### قدم ۲: ساخت تنظیم محلی و پایگاه‌داده

```bash
python tools/local-dev.py init
python tools/local-dev.py migrate
```

- `init` فایل `.env.local` خصوصی و یک پایگاه‌داده‌ی SQLite خالی در `.local/` می‌سازد.
- یک مقدار تصادفی برای `NORA_OTP_PEPPER` (کلید کپچا و OTP محلی) خودکار ساخته می‌شود. نیازی به تنظیم دستی نیست.
- هیچ کلید سرویس خارجی لازم نیست. اگر `.env.local` کلید خارجی داشته باشد، launcher آن را رد می‌کند.
- **فایل `.env.local` و پوشهٔ `.local/` را هرگز در Git یا ZIP عمومی قرار ندهید.** این دو در `.gitignore` هستند.

### قدم ۳: (اختیاری) ساخت حساب مدیر محلی

```bash
python tools/local-dev.py init --owner
```

این گزینه گذرواژه را پنهان می‌پرسد (حداقل ۱۲ نویسه). اگر `.env.local` از قبل وجود دارد، این مرحله را جداگانه و با دقت انجام دهید؛ `init` فایل موجود را بازنویسی نمی‌کند.

### قدم ۴: اجرای سرور

```bash
python tools/local-dev.py serve --host 127.0.0.1 --port 8000
```

سپس مرورگر را باز کنید:

- خانه: <http://127.0.0.1:8000/home.html>
- ورود: <http://127.0.0.1:8000/login.html>
- حساب: <http://127.0.0.1:8000/account.html>

برای دیدن از گوشی روی همان شبکه، `--host 0.0.0.0` بگذارید (فقط در شبکهٔ مطمئن).

### قدم ۵: بررسی وضعیت

```bash
python tools/local-dev.py check
```

این فرمان تنظیم و نسخهٔ پایگاه‌داده را نشان می‌دهد؛ مقدار هیچ رمزی را چاپ نمی‌کند.

---

## ۵. ورود و ارسال کد (وضعیت واقعی)

- **کپچا:** روی صفحهٔ ورود تصویر کد نمایش داده می‌شود و سرور آن را صادر و تأیید می‌کند. این بخش در محیط محلی کار می‌کند.
- **ارسال کد پیامکی (OTP):** برای ارسال واقعی به **کلید سرویس سفیر** نیاز دارد (`SAFIR_API_KEY` و `SAFIR_BOT_ID`). این کلیدها در محیط محلی تنظیم نشده‌اند، چون launcher محلی کلید خارجی را نمی‌پذیرد. در محیط محلی، سرور پیام صادقانهٔ «سرویس ارسال کد تنظیم نشده است» می‌دهد.
- **ورود مدیر:** با `NORA_OWNER_USERNAME` و گذرواژه‌ای که در `init --owner` ساخته‌اید.

## ۶. آزمون‌ها

### آزمون سرور (Python)

```bash
pip install -r backend/requirements-dev.txt
python -m pytest backend/tests
```

نتیجهٔ ثبت‌شدهٔ این بسته: **۱۴۷ قبول، ۴ اسکیپ** (اسکیپ‌ها به سرویس یا محیط خارجی نیاز دارند).

### آزمون صفحات (Node)

آزمون‌های `*.test.mjs` به `jsdom` نیاز دارند. یک بار در پوشه‌ای که Node دسترسی دارد نصب کنید:

```bash
npm install jsdom
node login.test.mjs
node smoke.test.mjs
```

نتیجه‌های ثبت‌شده: `login` ۸۱ بررسی، `smoke` ۷۷۷ بررسی، بقیه با کد خروج صفر. اگر فایلی خط شمارش نداشت، فقط کد خروج آن ثبت شده است.

**قاعده:** آزمونی که اجرا نشده، «موفق» حساب نمی‌شود.

---

## ۷. استقرار روی سرور (خلاصه)

جزئیات کامل در پوشهٔ `deployment/` بسته‌ی اصلی است (قالب‌های systemd، Caddy و نمونه‌ی تنظیمات). خلاصهٔ مسیر:

1. سرور Linux با Python 3.11 و PostgreSQL.
2. کد را در `/opt/nora` بگذارید و `backend/requirements.txt` را نصب کنید.
3. تنظیمات واقعی را فقط در `/etc/nora/nora-web.env` بگذارید (از `nora-web.env.example` کپی کنید). مقادیر واقعی را **هیچ‌جای دیگر** ننویسید.
4. `NORA_DATABASE_URL`، `NORA_OWNER_*`، `NORA_OTP_PEPPER` (مقدار جدید و خصوصی)، `SAFIR_API_KEY`، `SAFIR_BOT_ID` را تنظیم کنید.
5. `NORA_COOKIE_SECURE=true` و `NORA_PUBLIC_BASE_URL` را برای دامنهٔ واقعی بگذارید.
6. سرویس systemd را فعال کنید و Caddy را برای HTTPS پشت دامنه قرار دهید.
7. قبل از اعلام عمومی، آزمون ورود، ثبت فرم و پنل مدیر را روی دامنهٔ واقعی انجام دهید.

---

## ۸. امنیت: قواعد ثابت

- هیچ توکن، رمز، شماره‌ی تلفن واقعی یا `.env` واقعی در Git و ZIP نباشد.
- `.env.local` محلی است؛ مقدار واقعی در سرور فقط در `/etc/nora` باشد.
- کلید کیف پول بله (در پنل مالک) در پایگاه‌داده رمزنگاری می‌شود و فقط hint آن نمایش داده می‌شود.
- نشست مالک با کوکی `HttpOnly` و `SameSite=Strict` است؛ درخواست‌های تغییر وضعیت CSRF دارند.
- پیام‌های خطا برای کاربر فارسی و بدون جزئیات فنی‌اند.

---

## ۹. وضعیت فعلی: چه کامل است و چه نه

**کامل و آزمایش‌شده:**
- ورود: کپچای واقعی، صفحهٔ ورود با نوار ناوبری، پیام صادقانهٔ خطا، بدون اسپینر ابدی.
- درخواست ورود از مرورگر به سرور (بعد از رفع خطای Origin).
- رنگ هشدار و ساختار منوی مدیران طبق تصمیم شما.
- خانه: ظاهر از طراحی؛ بنر و استوری فقط با داده‌ی واقعی سرور نمایش داده می‌شوند.
- بک‌اند: ۱۴۷ آزمون قبول.

**ناقص یا انجام‌نشده:**
- **ارسال پیامک واقعی:** نیاز به کلید سفیر روی سرور دارد.
- **رویدادها:** ادغام دسته‌بندی و تقویم ماهانه از نسخهٔ طراحی هنوز انجام نشده؛ منتظر تأیید شماست.
- **حساب، پنل مدیریت، فرم‌ساز:** ادغام ظاهر طبق نقشه هنوز کامل نیست.
- **بررسی بصری:** فقط نمای موبایل ۳۹۰ پیکسل بررسی شده؛ دسکتاپ و حالت شب هنوز.
- **E2 تا E5 و تست ویندوز:** انجام نشده.

جزئیات دقیق هر ردیف در `FINAL-MISSION-MATRIX-fa.md` و `MERGE-MAP-fa.md` است.

## ۱۰. مشکلات رایج و راه‌حل

| مشکل | علت | راه‌حل |
|---|---|---|
| `init` می‌گوید `.env.local` از قبل هست | قبلاً ساخته شده | همان را نگه دارید؛ برای ساخت دوباره ابتدا فایل را دستی پاک کنید (فقط در محیط آزمایشی) |
| ورود کار نمی‌کند، پیام «سرویس ارسال کد تنظیم نشده» | کلید سفیر نیست | طبیعی در محیط محلی است؛ بخش ۵ را ببینید |
| کپچا بارگذاری نمی‌شود | سرور اجرا نیست یا پورت اشتباه | `serve` را بررسی کنید؛ دکمهٔ «کد جدید» را بزنید |
| صفحه بدون استایل است | مرورگر کش قدیمی دارد | Ctrl+F5 یا پاک‌کردن کش |
| `pytest` پیدا نمی‌شود | `requirements-dev.txt` نصب نشده | قدم بخش ۶ را انجام دهید |
| پورت ۸۰۰۰ اشغال است | فرایند دیگری روی آن است | پورت دیگری بدهید: `--port 8010` |

## ۱۱. گام‌های بعدی پیشنهادی

1. کلید سفیر و pepper واقعی را روی سرور تنظیم کنید.
2. تصمیم دربارهٔ دسته‌بندی و تقویم رویدادها را بدهید.
3. نسخهٔ دامنه را روی سرور راه‌اندازی و آزمون واقعی ورود و فرم را انجام دهید.
4. گزارش‌های `reports/` را بخوانید و موارد باز را یکی‌یکی ببندید.
