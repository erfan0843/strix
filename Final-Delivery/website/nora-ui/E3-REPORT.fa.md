# گزارش E3: گزارش و داشبورد سروری

تاریخ: ۱۵ اکتبر ۲۰۲۶

## هدف طبق نقشه

داشبورد فقط از `GET /api/admin/reports/summary` داده بگیرد. اگر API خطا بدهد یا نباشد، داده‌ی محلی یا نمونه جای آن نیاید.

## بررسی کد

- `admin.js` تابع `loadServerReports` را دارد. اگر رابط سرور نباشد، فقط پیام خطا نشان می‌دهد و `renderBody` را اجرا می‌کند؛ داده‌ی محلی جایگزین نمی‌شود.
- خطاهای ۴۰۳ (بدون مجوز)، ۰ (شبکه) و بقیه پیام‌های جدا دارند.
- داده‌ی پاسخ فقط وقتی پذیرفته می‌شود که `source` برابر `shared_server_database` و `period` درخواست‌شده باشد و ساختار عددی درست داشته باشد؛ در غیر این صورت خطای `invalid_report_summary` ثبت می‌شود.

## آزمون‌های موجود

| آزمون | نتیجه |
|---|---|
| `backend/tests/test_workflows_api.py` (گزارش خلاصه، پریود نامعتبر، دسترسی بدون نشست) | قبول (در بخش بک‌اند) |
| `admin.test.mjs` | قبول |
| `admin-rbac.test.mjs` | قبول |

## باقی‌مانده

- آزمون زنده‌ی مالک در مرورگر روی نسخه‌ی محلی (ورود، باز کردن گزارش، مشاهده‌ی عدد واقعی یا حالت خالی) هنوز انجام نشده است. این بخش باید با تو روی ویندوز انجام شود.
- پذیرش روی staging بعد از فاز ۶ انجام می‌شود.

## نتیجه

کد و آزمون‌های E3 مطابق نقشه‌اند؛ هیچ داده‌ی نمونه یا محلی جایگزین خطای سرور نمی‌شود. گام بعد: **E4 (برش عمودی فرم)**.
