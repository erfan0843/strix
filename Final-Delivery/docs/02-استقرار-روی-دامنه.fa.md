# راهنمای استقرار وب‌سایت و بات بله روی سرور و دامنه شخصی

این راهنما یک نقشه‌ی عملی است. قالب‌ها در `deployment/` هستند؛ قبل از استفاده روی سرور واقعی باید بررسی شوند. **این بسته روی سرور واقعی و دامنه‌ی شما تست نشده است.**

## ۱. سرور
- Ubuntu 22.04 یا 24.04 (یا Debian 12) با حداقل ۲ گیگ رم، دسترسی sudo و IP ثابت.
- پورت‌های باز: ۲۲ (SSH)، ۸۰ و ۴۴۳ (HTTP/HTTPS). پورت ۸۰۰۰ (نورا) فقط داخلی است و نباید عمومی باشد.

## ۲. دیتابیس
- توصیه: PostgreSQL 16. نصب: `sudo apt install postgresql`.
- یک کاربر و یک دیتابیس بسازید و رمز را فقط در `/etc/nora/nora-web.env` بگذارید.
- **هشدار:** migrationهای نورا روی PostgreSQL هنوز کامل تست نشده‌اند (در بخش محدودیت‌ها توضیح داده شده). قبل از داده‌ی واقعی، یک بار روی کپی آزمایشی اجرا کنید.
- پشتیبان روزانه: `pg_dump -Fc nora > /var/backups/nora-$(date +%F).dump` و یک کپی خارج از سرور.

## ۳. کپی فایل‌ها به سرور
از لپ‌تاپ (با scp):
```bash
scp -r website bale-bot deployment user@SERVER_IP:/tmp/nora/
```
سپس روی سرور:
```bash
sudo useradd --system --home /opt/nora --shell /usr/sbin/nologin nora
sudo mkdir -p /opt/nora /etc/nora /opt/nora/data
sudo cp -r /tmp/nora/website /tmp/nora/bale-bot /opt/nora/
sudo chown -R nora:nora /opt/nora
```

## ۴. پیش‌نیازهای پایتون
```bash
sudo apt install -y python3.11 python3.11-venv
sudo python3.11 -m venv /opt/nora/venv
sudo /opt/nora/venv/bin/pip install -r /opt/nora/website/nora-ui/backend/requirements.txt -r /opt/nora/bale-bot/nora_bot/requirements.txt
```

## ۵. تنظیمات محرمانه
```bash
sudo cp /tmp/nora/deployment/nora-web.env.example /etc/nora/nora-web.env
sudo cp /tmp/nora/deployment/bale-bot.env.example /etc/nora/bale-bot.env
sudo chmod 600 /etc/nora/*.env && sudo chown nora:nora /etc/nora/*.env
sudo nano /etc/nora/nora-web.env   # مقادیر واقعی را شما وارد کنید
```
مقادیر در `docs/03` توضیح داده شده‌اند. هیچ مقدار واقعی را در گفت‌وگو، Git یا ZIP قرار ندهید.

## ۶. سرویس‌ها
```bash
sudo cp /tmp/nora/deployment/nora-web.service /etc/systemd/system/
sudo cp /tmp/nora/deployment/nora-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now nora-web
sudo systemctl enable --now nora-bot
systemctl status nora-web nora-bot --no-pager
```
پس از ریبوت، هر دو خودکار بالا می‌آیند (`enable`).

## ۷. وب‌سرور و HTTPS (Caddy)
1. رکورد DNS را در پنل دامنه بسازید: رکورد `A` برای `lifeline1.ir` و `www` به IP سرور. این را خودتان انجام دهید؛ من آن را بررسی نکرده‌ام.
2. Caddy را نصب کنید (`sudo apt install caddy`)، سپس `deployment/Caddyfile` را به `/etc/caddy/Caddyfile` کپی کنید و `sudo systemctl reload caddy` بزنید.
3. Caddy گواهی را خودکار می‌گیرد و تمدید می‌کند، به شرط اینکه DNS درست باشد و پورت‌های ۸۰/۴۴۳ باز باشند.
4. بررسی: `curl -I https://lifeline1.ir/` باید ۲۰۰ یا ۳۰۲ بدهد.

## ۸. فایروال
```bash
sudo ufw allow OpenSSH && sudo ufw allow 80,443/tcp && sudo ufw enable
```
پورت ۸۰۰۰ را باز نکنید (فقط داخلی است).

## ۹. لاگ و سلامت
- وب: `journalctl -u nora-web -f`
- ربات: `journalctl -u nora-bot -f`
- سلامت: `curl -s http://127.0.0.1:8000/api/health` روی سرور (اگر خطای `database_not_configured` دیدید، دیتابیس تنظیم نشده است).

## ۹-ب. رفتار راه‌اندازی ربات و گاردِ دادهٔ جداگانه

### چرا ربات ممکن است با کد خروج ۲ متوقف شود؟
ربات در حالت پیش‌فرض **عمداً اجرا نمی‌شود** تا زمانی که انتقال همهٔ قابلیت‌ها به API مشترک کامل نشده باشد. دلیلش این است که بخشی از قابلیت‌های قدیمی ربات (رویدادها، فرم‌های قدیمی، پرداخت، حضور و غیاب و گواهی‌ها) هنوز روی SQLite مستقل خودش کار می‌کند. اگر ربات بدون تصمیم صریح شما بالا بیاید، همان داده در دو جای متفاوت ثبت می‌شود و یک مرجع واحد نخواهیم داشت.

بنابراین `main.py` پیش از هر کاری این را بررسی می‌کند:

```python
if os.getenv("NORA_BOT_ALLOW_LEGACY_SQLITE") != "1":
    print("ربات اجرا نشد: اتصال به پایگاه مشترک هنوز کامل نیست؛ ...")
    return 2
```

خروجی روی سرور در `journalctl -u nora-bot` چنین چیزی است:

```
ربات اجرا نشد: اتصال به پایگاه مشترک هنوز کامل نیست؛ فعلاً اجرا را بسته‌ایم تا داده‌ها در پایگاه جداگانه ثبت نشوند.
```

این توقف **قبل از ساخت پایگاه** رخ می‌دهد؛ یعنی در این حالت هیچ فایل SQLite تازه‌ای ساخته یا تغییر نمی‌شود. قالب `deployment/nora-bot.service` کد خروج ۲ را با `RestartPreventExitStatus=2` از ری‌استارت بیرون می‌گذارد، وگرنه systemd هر ۱۰ ثانیه بی‌پایان ری‌استارت می‌کرد.

### تحت چه شرایطی اجرای قابلیت‌های legacy مجاز است؟
فقط وقتی **خودتان صریحاً** تصمیم گرفته باشید که فعلاً قابلیت‌های قدیمی ربات باید مستقل کار کنند:

```bash
sudo nano /etc/nora/bale-bot.env
# این خط را اضافه کنید:
NORA_BOT_ALLOW_LEGACY_SQLITE=1
sudo systemctl restart nora-bot
```

### پیش‌نیازهای این حالت
پیش از روشن‌کردن این متغیر، این‌ها باید برقرار باشند:

1. `NORA_SHARED_API_URL` روی مبدأ درست تنظیم شده باشد و پیشوند `/api` نداشته باشد.
2. `NORA_BOT_SERVICE_TOKEN` در ربات و بک‌اند **دقیقاً یکی** باشد (حداقل ۳۲ نویسه).
3. `SUPER_ADMIN_ID` ربات با `NORA_OWNER_BALE_USER_ID` در بک‌اند یکی باشد؛ در غیر این‌صورت ربات با کد ۱ و پیام «شناسهٔ اپراتور ربات در پایگاه مشترک نقش مالک ندارد» بالا نمی‌آید.
4. `DB_PATH` به مسیر `/opt/nora/data/nora-bot.sqlite3` اشاره کند و کاربر `nora` روی آن پوشه اجازهٔ نوشتن داشته باشد.

پیش از روشن‌کردن این متغیر، بررسی کنید که API واقعاً در دسترس است:

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://YOUR_DOMAIN/api/health
```

### پذیرش جدایی داده‌ها به چه معناست؟
با روشن‌بودن این متغیر، بخشی از قابلیت‌های ربات (رویدادها، فرم‌های قدیمی، پرداخت، حضور و غیاب و گواهی‌ها) روی SQLite محلی کار می‌کند و بخشی دیگر (هویت، فرم‌های سروری، کارتابل، اعلان‌ها و تحویل فایل) روی PostgreSQL بک‌اند. یعنی:

- دادهٔ آن قابلیت‌های قدیمی در گزارش‌های بک‌اند دیده نمی‌شود.
- یک کاربر می‌تواند در بک‌اند حساب داشته باشد و در SQLite ربات هم ردیف جدا داشته باشد؛ این دو **خودکار ادغام نمی‌شوند**.
- پشتیبان‌گیری باید **برای هر دو منبع جداگانه** انجام شود.

این وضعیت موقتی و آگاهانه است. تا زمانی که مهاجرت کامل نشده، مستندات این جدایی را پنهان نمی‌کنند.

### پشتیبان‌گیری
بک‌اند (منبع اصلی مسیرهای مشترک):
```bash
pg_dump -Fc nora > /var/backups/nora-$(date +%F).dump
```
SQLite ربات (فقط اگر حالت legacy روشن است):
```bash
sudo -u nora sqlite3 /opt/nora/data/nora-bot.sqlite3 ".backup '/var/backups/nora-bot-$(date +%F).sqlite3'"
```
پیش از هر به‌روزرسانی یا مهاجرت، **هر دو** پشتیبان را بگیرید و کپی را خارج از سرور نگه دارید. ربات خودش هم بک‌آپ دوره‌ای می‌گیرد (`AUTO_BACKUP_HOURS`).

### بررسی وضعیت سرویس و خطاهای راه‌اندازی
```bash
systemctl status nora-bot nora-web --no-pager
journalctl -u nora-bot -n 100 --no-pager
journalctl -u nora-web -n 100 --no-pager
```
کدهای خروج ربات معنای مشخص دارند:

| کد | معنا | کار |
|---|---|---|
| ۲ | توقف عمدی گارد legacy | یا آگاهانه `NORA_BOT_ALLOW_LEGACY_SQLITE=1` را تنظیم کنید، یا ربات را خاموش بگذارید |
| ۱ | خطای پیکربندی، فایل گمشده، قفل نمونهٔ دوم، یا نرسیدن به API | پیام‌های بالای لاگ را بخوانید؛ خطاها در همان‌جا نام‌گذاری شده‌اند |
| ۰ | خاموشی تمیز | — |

### بازگشت امن در صورت بروز مشکل
1. سرویس را متوقف کنید: `sudo systemctl stop nora-bot`.
2. خط `NORA_BOT_ALLOW_LEGACY_SQLITE=1` را از `/etc/nora/bale-bot.env` بردارید (یا کامنت کنید) تا ربات به حالت پیش‌فرض امن برگردد.
3. اگر داده‌ای آسیب دید، از پشتیبان بازیابی کنید:
   `sudo systemctl stop nora-bot && sudo -u nora sqlite3 /opt/nora/data/nora-bot.sqlite3 ".restore '/var/backups/nora-bot-DATE.sqlite3'"`.
4. `sudo systemctl start nora-bot` و بعد `journalctl -u nora-bot -n 50 --no-pager` را ببینید.

### قرارداد نشانی API
`NORA_SHARED_API_URL` فقط **مبدأ** است و مسیر `/api` را خودِ کلاینت ربات اضافه می‌کند:

```
NORA_SHARED_API_URL = https://lifeline1.ir      ✅
NORA_SHARED_API_URL = https://lifeline1.ir/api  ❌ خطای shared_api_url_invalid
```

اگر نشانی مسیر، query یا fragment داشته باشد، ربات در همان بررسی راه‌اندازی با کد ۱ و پیام روشن متوقف می‌شود. `http` فقط برای `localhost` و `127.0.0.1` مجاز است.

## ۱۰. پشتیبان و بازگشت
- پشتیبان دیتابیس: `pg_dump -Fc` روزانه با cron و نگهداری کپی خارج از سرور.
- بازیابی: `pg_restore -d nora FILE.dump` روی دیتابیس خالی (ابتدا روی کپی آزمایش کنید).
- بازگشت به نسخه‌ی قبل: پوشه‌ی قبلی `/opt/nora` را نگه دارید؛ با `systemctl stop`، جایگزینی، و `systemctl start` برمی‌گردید.

## ۱۱. به‌روزرسانی
1. پشتیبان بگیرید. 2. فایل‌های جدید را در `/tmp` بگذارید. 3. سرویس‌ها را متوقف کنید. 4. کپی و `pip install`. 5. migration را اجرا کنید. 6. سرویس‌ها را روشن کنید و سلامت را بررسی کنید.

## ۱۲. موارد SEO و دامنه
- در فایل‌های عمومی این بسته (HTML، robots.txt، llms.txt) دامنه‌ی مشخصی هاردکد نشده است. پس از اتصال دامنه، آدرس‌های canonical و sitemap را با دامنه‌ی واقعی شما بررسی و در صورت نیاز تنظیم کنید؛ من این بخش را روی دامنه‌ی زنده تأیید نکرده‌ام.
- robots.txt و llms.txt ابزار حفاظت یا تضمین نمایش نیستند.
