# توکن بات بله و امنیت اطلاعات محرمانه

## قاعده‌ی اصلی
توکن‌ها، کلیدها، رمزها و شماره‌ی تلفن واقعی **هرگز** داخل کد، ZIP، Git، مستندات یا گفت‌وگو قرار نمی‌گیرند. فقط در فایل محیطی روی سیستمی که اجرا می‌شود نگهداری می‌شوند.

## کجا باید تنظیم شوند
| مقدار | بخش | فایل |
|---|---|---|
| `BOT_TOKEN` | ربات بله | `bale-bot/nora_bot/.env` (محلی) یا `/etc/nora/bale-bot.env` (سرور) |
| `SUPER_ADMIN_ID` | ربات بله | همان |
| `SAFIR_API_KEY`، `SAFIR_BOT_ID` | ارسال OTP از طریق سفیر (اختیاری) | همان |
| `NORA_BOT_SERVICE_TOKEN` | مشترک بین ربات و وب | هر دو فایل، باید یکسان باشد |
| `NORA_DATABASE_URL`، `NORA_OTP_PEPPER`، `NORA_OWNER_*` | وب | `website/nora-ui/.env.local` (محلی) یا `/etc/nora/nora-web.env` |

## روش امن
1. فایل `.env.example` را کپی کنید و نام آن را به `.env` تغییر دهید. این فایل در `.gitignore` باشد.
2. مجوز فایل را محدود کنید: `chmod 600 .env` (لینوکس).
3. هرگز `.env` را برای کسی ارسال نکنید، در Git commit نکنید و در اسکرین‌شات نگذارید.
4. هر توکنی که در گفت‌وگو، ایمیل یا پیام عمومی دیده شد، **بازسازی (rotate)** کنید: در پنل بله (BotFather یا پنل بات) توکن جدید بگیرید و فایل محلی/سرور را به‌روز کنید.
5. روی سرور، کاربر سرویس باید `nologin` باشد و فقط به `/etc/nora` دسترسی خواندن داشته باشد.

## وضعیت این بسته
- در این بسته هیچ مقدار واقعی وجود ندارد (بررسی با الگوهای توکن، کلید و شماره تلفن انجام شد؛ نتیجه در گزارش تست است).
- نمونه‌های `SUPER_ADMIN_ID` و شماره‌ها در کد تست، مقدار ساختگی هستند.
- ارسال OTP و پرداخت واقعی در این بسته اجرا یا آزمایش نشده‌اند؛ این کار بدون درخواست صریح شما انجام نمی‌شود، چون پیامک و هزینه‌ی واقعی دارد.

## چرخش توکن از پنل (بدون ویرایش دستی فایل محیطی)

از این نسخه، اعتبارنامه‌های وب از مسیر «تنظیمات ← اتصال سرویس‌ها» مدیریت می‌شوند:

| مقدار | جای ذخیره | یادداشت |
|---|---|---|
| `NORA_BALE_BOT_TOKEN` | رمزنگاری‌شده در پایگاه (اولویت) یا محیط | **مصرف: وب + ربات legacy.** ذخیره در پنل فقط وب را عوض می‌کند؛ ربات همین توکن را از `BOT_TOKEN` در `bale-bot.env` می‌خواند و باید جداگانه به‌روز و راه‌اندازی شود (پنل این را کنار فیلد نشان می‌دهد و تأیید «راه‌اندازی دوباره» می‌گیرد). |
| `NORA_FORM_PAYMENT_BOT_TOKEN` («توکن ربات پرداخت») | همان | **مصرف: فقط وب.** توکن Bot API رباتِ مستقل پرداخت (`شناسه:رمز`)؛ در `/bot<token>/` و HMAC مسیر وب‌هوک. توکن کیف پول در این فیلد رد می‌شود (`invalid_payment_bot_token`). |
| `NORA_FORM_PAYMENT_PROVIDER_TOKEN` («توکن پرداخت کیف پول بله / Provider Token») | همان | **مصرف: فقط وب.** مقدار `provider_token` در `createInvoiceLink`؛ برای پرداخت الزامی است. مقداری با شکل Bot API در این فیلد رد می‌شود (`provider_token_must_not_be_bot_token`). هیچ کپی خودکاری بین این دو نیست. |
| `NORA_FORM_PAYMENT_WEBHOOK_SECRET` | همان | **مصرف: فقط وب.** نشانی ثبت‌شدهٔ وب‌هوک و تأیید درخواست بازگشتی هر دو از همین مقدار مؤثر ساخته می‌شوند. |
| `SAFIR_API_KEY` | همان | **مصرف: وب + ربات legacy** (`SAFIR_API_KEY` در `bale-bot.env`). اگر `NORA_OTP_PEPPER` مستقل تنظیم نشده باشد، ذخیره رد می‌شود؛ چون تعویض کلید نباید هش هویت را عوض کند. |
| `BOT_TOKEN`، `SUPER_ADMIN_ID` | فقط فایل محیطی ربات | پنل وب به فرایند ربات دسترسی ندارد؛ این‌ها از پنل تغییر نمی‌کنند. |
| `NORA_OTP_PEPPER`، `NORA_OWNER_BALE_USER_ID`، `NORA_BOT_SERVICE_TOKEN` | فقط محیط | تغییر از پنل عمداً ممکن نیست: اولی هش هویت را می‌سازد، دومی نقش مالک را تعیین می‌کند و سومی باید هم‌زمان در ربات عوض شود. |

قواعد پنل:
1. مقدار محرمانه هرگز در پاسخ API برنمی‌گردد؛ فقط چهار نویسهٔ پایانی، منبع (پایگاه/محیط) و زمان آخرین تغییر.
2. فیلد خالی چیزی را ذخیره یا حذف نمی‌کند؛ حذف دکمهٔ جداگانه با تأیید صریح است.
3. هر ذخیره/حذف/آزمایش در گزارش سرور با شناسهٔ سرویس، نوع عملیات، زمان، نتیجه و شناسهٔ مدیر ثبت می‌شود؛ مقدار در گزارش نیست.
4. «تنظیم‌شده» به معنی «متصل» نیست. تنها آزمایش واقعی، فراخوانی فقط‌خواندنی `getMe` بله برای توکن ربات اصلی/ربات پرداخت است. برای کلید پیامک آزمایش بی‌اثر وجود ندارد و وضعیت «تنظیم‌شده · آزمایش‌نشده» می‌ماند.
5. **مقدار ذخیره‌شده همان مقدار مصرف‌شده است.** همهٔ مسیرهای وب که به اعتبارنامه وابسته‌اند (ورود مینی‌اپ، OTP، آمادگی پرداخت در `health`/`capabilities`/readiness/انتشار، `payment-intent`، `createInvoiceLink`، نشانی و تأیید وب‌هوک، تأیید نهایی) از لایهٔ مؤثر «پایگاه روی محیط» می‌خوانند. پنل برای هر سرویس بلوک «وضعیت عملیاتی در وب» را از همین لایه نشان می‌دهد (`runtime.ready/missing`)؛ «فعال در وب» با «آزمایش‌شده» یکی نیست و پرداخت فقط با هر چهار مقدار معتبر فعال می‌شود.
6. **دامنهٔ اثر.** پنل زیر هر فیلد می‌گوید کدام فرایند آن را مصرف می‌کند. هیچ راه‌اندازی خودکار یا نوشتن فایل محیطی سرور از پنل وجود ندارد؛ چرخش برای ربات legacy همچنان دستی است.

## کلید رمزنگاری اعتبارنامه‌ها

- نام: `NORA_SETTINGS_ENCRYPTION_KEY` (Fernet)، فقط در فایل محیطی سرور؛ در Git نیست.
- باید **مستقل** از پایگاه‌داده، توکن ربات، توکن پرداخت و `NORA_OTP_PEPPER` ساخته شود:
  `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`
- گم‌شدن این کلید یعنی مقدارهای ذخیره‌شده در پایگاه دیگر خوانا نیستند (رمزنگاری‌شده می‌مانند ولی قابل بازیابی نیستند)؛ مقدار محیطی (اگر باشد) دوباره اعمال می‌شود.
- اگر کلید تنظیم نشده باشد، پنل هیچ مقدار ساده‌ای ذخیره نمی‌کند و صریح خطا می‌دهد.
