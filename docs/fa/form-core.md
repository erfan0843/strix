# فرم، هستهٔ سامانه

> تصمیم بنیادی: **در این سامانه فرم یک «بخش» نیست؛ خودِ سامانه است.**
> هر چیزی که داده وارد می‌کند — ثبت‌نام، نظرسنجی، پشتیبانی، عضویت، کمک، سفارش، حضور، آزمون، شکایت، درخواست — یک فرم است.
> هیچ جای دیگری «فرمِ جدا» ساخته نمی‌شود و هیچ داده‌ای بیرون از فرم ثبت نمی‌شود.

---

## ۱) یک اصل، چهار نتیجه

**اصل:** تنها راه ورود داده به سامانه، «فرم» است.

| نتیجه | معنا |
| --- | --- |
| یک نقطهٔ ورود | کارشناس همیشه از یک جا شروع می‌کند: فرم تازه. |
| یک مدل داده | همه‌چیز در `forms → responses → answers` می‌نشیند؛ نه جدول اختصاصی هر ماژول. |
| یک موتور اعتبارسنجی | کد ملی، موبایل، شبا، تاریخ، شرط‌ها — یک‌بار نوشته می‌شود، همه‌جا کار می‌کند. |
| یک زنجیرهٔ خروجی | acknowledgment، بلیت، گواهینامه، فاکتور، پیام، وبهوک — همه از یک «پاسخ» بیرون می‌آیند. |

---

## ۲) شش لایهٔ هر فرم

هر فرم دقیقاً این شش لایه را دارد. لایه‌ها خاموش/روشن می‌شوند، ولی ساختار یکی است.

| لایه | چه چیزی داخلش است |
| --- | --- |
| **۱ ساختار** | سوال‌ها، ترتیب، گروه و مرحله، پیش‌فرض‌ها، متن راهنما |
| **۲ جریان** | شرط نمایش، پرش، چند مرحله‌ای، ذخیرهٔ نیمه‌کاره، اعتبارسنجی |
| **۳ دسترسی** | عمومی/لینک/کد/افراد، بازه، ظرفیت، هر‌نفر‌یک‌بار، احراز، پروفایل |
| **۴ کارشناس** | چه کسی ببیند، چه کسی تأیید کند، چه کسی خروجی بگیرد |
| **۵ خروجی** | پیام تأیید، بلیت، گواهینامه، آیدی‌کارت، QR، فاکتور، ایمیل/پیامک |
| **۶ پول** | رایگان/پرداخت، روش‌ها، تخفیف، اقساط، تأیید پرداخت |

دو قاعدهٔ سخت‌گیر:
- هر لایه‌ای که روشن می‌شود، **تست خودش** را دارد.
- هیچ لایه‌ای بدون «پاسخ» معنا ندارد؛ پس سیستم فقط با پاسخ‌ها زنده است.

---

## ۳) هر ماژول = یک فرم + چند قابلیت

نگاشت امروزِ سامانه به فرم:

| ماژول امروز | در مدل جدید |
| --- | --- |
| ثبت‌نام دوره/کارگاه | فرم + قابلیت پرداخت + بلیت + گواهینامه |
| رویداد | فرم + قابلیت جلسه و حضور + کارت ورود |
| نظرسنجی / رضایت‌سنجی | فرم + قابلیت ناشناس + آمار |
| آزمون | فرم + قابلیت نمره + زمان + تصادفی‌سازی |
| عضویت / همکاری با ما | فرم + قابلیت پروفایل + تأیید کارشناس |
| کمک و حمایت مالی | فرم + قابلیت پرداخت + رسید |
| سفارش و فروش | فرم + قابلیت آیتم، موجودی، ارسال |
| پشتیبانی و شکایت | فرم + قابلیت کارتابل + پیگیری با کد |
| حضور و غیاب | فرم + قابلیت جلسه + بازهٔ ثبت |
| صندوق و تسویه | **نما** روی پاسخ‌های مالی، نه بخش مستقل |

پس فهرست ماژول‌ها از بین می‌رود و جایش این می‌آید:
**۱) فرم‌ها ۲) پاسخ‌ها ۳) کارشناسان ۴) خروجی‌ها ۵) تنظیمات.**

---

## ۴) نقش‌ها

| نقش | کار |
| --- | --- |
| مالک سامانه | همهٔ فرم‌ها، ساخت قالب سازمانی، تعیین کارشناسان |
| سازندهٔ فرم | ساخت و ویرایش فرم، دیدن پاسخ، خروجی |
| کارشناس | فقط پاسخ‌های فرم‌های سپرده‌شده؛ تأیید/رد و یادداشت |
| بیننده | فقط گزارش، بدون تغییر |
| کاربر | پر کردن، پیگیری با کد، ویرایش/انصراف اگر باز باشد |

قاعده: **مجوز، سرورساید.** رابط کاربری فقط دکمه‌ها را کم و زیاد می‌کند.

---

## ۵) قرارداد کد (تا فردا خراب نشود)

1. هر فرم یک **کلید پایدار** دارد؛ تغییر عنوان، آدرس را عوض نمی‌کند.
2. پاسخ‌ها **هرگز حذف سخت** نمی‌شوند؛ وضعیت `withdrawn` می‌گیرند.
3. تغییر در سوال‌ها **نسخه** می‌خورد؛ پاسخ‌های قدیم به نسخهٔ خودشان می‌چسبند.
4. خروجی‌ها (بلیت/گواهینامه) **تابع پاسخ‌اند**، نه جدول جدا؛ با تغییر پاسخ بازتولید می‌شوند.
5. هر قابلیت **قابل خاموش شدن** است؛ فرم بدون آن هم کار می‌کند.
6. هیچ متنی در کد سخت‌کد نمی‌شود؛ همه از پنل ویرایش می‌شود.
7. هر قابلیت یک تست خودکار دارد؛ نبودش = نبودن قابلیت.

---

## ۶) قدم بعد: ریز‌به‌ریز ساخت فرم

ترتیب کارِ ساخت (هر قدم کوچک، تست سبز، بعد قدم بعد):

| گام | کار | خروجی قابل لمس |
| --- | --- | --- |
| ۱ | هستهٔ دادهٔ فرم: فرم، سوال، پاسخ، پاسخ‌سوال | مهاجرت + تست |
| ۲ | موتور نوع سوال: ۱۰ نوع پرکاربرد اول | ثبت و نمایش هر نوع |
| ۳ | اعتبارسنجی مشترک: موبایل، کد ملی، شبا، کارت، تاریخ | تست قاعده‌ها |
| ۴ | سازندهٔ ساختار: افزودن، جابه‌جایی، کپی، حذف | کارشناس یک فرم کامل می‌سازد |
| ۵ | جریان: شرط، مرحله، ذخیرهٔ نیمه‌کاره | نمایش شرطی کار می‌کند |
| ۶ | دسترسی: وضعیت، بازه، ظرفیت، لینک، کد | فرم منتشر می‌شود |
| ۷ | پر کردن کاربر (لینک → پایان) | یک نفر واقعاً پر می‌کند |
| ۸ | کارتابل کارشناس: تأیید، رد، یادداشت، برچسب | چرخهٔ تأیید بسته می‌شود |
| ۹ | خروجی‌ها: پیام، بلیت، QR | کد پیگیری و بلیت |
| ۱۰ | گزارش و خروجی اکسل | تحلیل و خروجی |
| ۱۱ | قابلیت‌های ویژه: پرداخت، آزمون، حضور، سفارش | هر قابلیت جدا و قابل خاموش‌شدن |
| ۱۲ | گواهینامه و آیدی‌کارت | خروجی نهایی |

هر گام: **کد + تست + دموی زنده**. تا گام ۷ تمام نشود، سراغ گام ۸ نمی‌رویم.
